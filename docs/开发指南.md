# CopyShare 开发指南

> 文档导航：[用户指南](用户指南.md) · [故障排查](故障排查.md) · [测试与构建](测试与构建.md) · [架构与扩展点](架构与扩展点.md) · [局域网协议](局域网协议.md)

本文说明如何在本地运行、调试和安全修改 CopyShare。模块级职责与不变量见[架构与扩展点](架构与扩展点.md)，网络消息与兼容规则见[局域网协议](局域网协议.md)。

## 1. 技术栈

- Tauri 2 + Rust：桌面生命周期、系统能力、持久化、局域网通信和文件传输。
- Vue 3 + TypeScript + Pinia：页面、组件、状态和前后端数据映射。
- Tailwind CSS：界面布局与主题样式。
- Node 内置测试运行器：前端行为、结构和文档契约测试。
- Cargo test：Rust 单元、状态机、网络、持久化和恢复测试。

## 2. 环境准备

需要安装：

- Node.js LTS 与 npm。
- Rust stable 工具链和 Cargo。
- 当前平台的 Tauri 2 系统依赖。

Windows 通常需要 Microsoft C++ Build Tools 与 WebView2；macOS 需要 Xcode Command Line Tools；Linux 需要 WebKitGTK、AppIndicator、图像/OCR 和打包工具。准确依赖以 [Tauri 2 prerequisites](https://v2.tauri.app/start/prerequisites/) 及 `.github/workflows/release.yml` 为准。

安装依赖并启动桌面开发模式：

```powershell
npm ci --legacy-peer-deps
npm run tauri:dev
```

只调试前端页面时可以运行 `npm run dev`，但纯浏览器环境没有 Tauri bridge，调用桌面命令时出现 `window.__TAURI_INTERNALS__` 缺失属于预期限制。

## 4. 调用与事件链路

典型前端调用路径：

```text
Vue 页面/组件 → Pinia store → src/lib/tauri.ts
→ Tauri command → Rust AppState/业务模块 → 磁盘或局域网
```

典型状态回传路径：

```text
Rust 运行时 → Tauri event → Pinia store → 页面响应式更新
```

- 前端不要直接拼接 invoke 名称，统一在 `src/lib/tauri.ts` 建立类型化包装。
- `commands.rs` 负责参数语义和编排，长期状态进入 `AppState`。
- 事件订阅必须允许重复安装并在窗口/页面卸载时释放。
- 网络身份、路径、大小、哈希和权限校验必须留在 Rust 层。

## 5. 常见开发流程

### 新增或修改配置项

1. 同步修改 Rust 和 TypeScript 的 `AppConfig`。
2. Rust 字段增加 serde 默认值。
3. 必要时提升 `CURRENT_CONFIG_VERSION` 并在迁移逻辑中保护老用户语义。
4. 更新前端默认配置、设置页面和中英文目录。
5. 增加“全新配置默认值”和“旧配置升级”测试。

### 新增 Tauri Command

1. 在对应业务模块实现能力。
2. 在 `commands.rs` 暴露命令入口。
3. 在 `lib.rs` 的 invoke handler 注册。
4. 在 `src/lib/tauri.ts` 添加类型化包装。
5. 由 store 或页面调用，并覆盖成功、失败和用户反馈。

### 新增 Tauri Event

1. 定义稳定、可序列化的 payload。
2. Rust 在状态实际提交后再发事件。
3. Store 集中安装监听并处理重复/乱序事件。
4. 页面只消费 store 状态，避免多个页面各自维护不同事件副本。

### 修改局域网协议

- 新字段优先设计为可选字段并提供 serde 默认值。
- 新能力通过 `Hello.capabilities` 协商。
- 收到消息后先验证当前 Socket 与设备身份，再改变业务状态。
- 字段删除、重命名或语义改变属于破坏性变更，需要协议版本和迁移测试。

### 新增持久化数据

- 业务模块负责默认值、迁移和容量上限。
- 单文件 JSON 使用 `safe_json_store`，不要直接覆盖主文件。
- 二进制资源放独立目录，JSON 只保存引用与校验信息。
- 覆盖 `.tmp`、`.bak`、损坏隔离和中断恢复测试。

## 6. 前端与多语言约定

- Vue 源码以中文源文案为主，英文映射维护在 `locales/en-US.json`。
- `locales/zh-CN.json` 同步登记中文目录，结构测试会检查遗漏。
- 用户正文、文件名、路径和剪贴板内容不能进入翻译目录；使用项目约定的忽略标记。
- 新页面优先复用现有主题变量、组件和间距体系，不引入并行视觉系统。
- 修改窗口拖拽、透明区域或全局快捷键时，同时检查主窗口、浮窗和平台差异。

生成/整理语言目录的脚本：

```powershell
node scripts/generate-i18n-catalog.mjs
```

运行前先补齐新增英文映射，避免生成后英文界面残留中文。

## 7. Rust 模块修改边界

- `sync_engine.rs` 只包含哈希、HLC、去重和回声抑制等纯状态逻辑。
- `sync.rs` 负责 WebSocket、信任、心跳和剪贴板编排。
- `file_transfer_paths.rs` 负责文件名和保存路径策略。
- `file_transfer.rs` 负责授权、worker、断点续传和任务状态。
- `safe_json_store.rs` 负责通用 JSON 事务，不负责业务字段迁移。
- `config.rs`、`device_store.rs`、`history.rs` 负责各自业务快照语义。

不要为了减少文件数量把网络、磁盘和状态机重新合并到一个模块。也不要扩大 `pub` 可见性来绕过测试；优先测试公开行为或使用 `cfg(test)` 辅助接口。

## 8. 调试建议

- 先使用新的纯文本验证连接，再测试图片和文件，逐层缩小问题范围。
- 网络问题同时观察发送端与接收端日志，确认失败发生在发现、握手、信任、控制消息还是数据流。
- 文件续传问题保留 `.part` 和任务快照，比较声明 offset 与磁盘实际长度。
- 持久化问题保留 `.tmp`、`.bak`、`.corrupt`，不要先删除现场。
- 浏览器预览只用于布局检查；桌面命令、托盘、剪贴板和文件系统行为必须在 Tauri 运行时验证。

## 9. 提交前检查

至少完成：

```powershell
node --test tests/*.test.ts
npm run build
cd src-tauri
cargo check
cargo test
```

然后回到仓库根目录运行 `git diff --check`。完整策略、打包命令和产物位置见[测试与构建](测试与构建.md)。
