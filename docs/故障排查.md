# CopyShare 故障排查

> 文档导航：[用户指南](用户指南.md) · [开发指南](开发指南.md) · [测试与构建](测试与构建.md) · [架构与扩展点](架构与扩展点.md) · [局域网协议](局域网协议.md)

本文按“先确认状态，再缩小范围”的顺序排查 CopyShare 常见问题。不要一开始就删除配置、历史或传输临时文件，这会丢失诊断现场和断点续传状态。

## 1. 快速诊断顺序

1. 确认两端 CopyShare 均已启动，版本和系统时间正常。
2. 查看主界面的同步状态，确认没有手动暂停。
3. 打开「设置 → 网络诊断」，检查本机地址、TCP/UDP 监听和防火墙提示。
4. 在「设备连接」确认设备是“已信任并已连接”，而不是只被发现或等待确认。
5. 查看「同步日志」和桌面通知中的具体错误。
6. 只针对失败环节重试，避免同时修改端口、防火墙、目录和信任状态。

## 2. 应用无法启动或窗口异常

### 启动后没有主窗口

- 检查系统托盘，CopyShare 可能已在后台运行。
- CopyShare 只允许单实例；再次启动会激活已有窗口，而不会创建第二个进程。
- 如果设置了“关闭时最小化到托盘”，关闭按钮和 `Alt+F4` 不会退出程序。
- 确认系统安全软件没有隔离当前安装目录中的主程序。

### 首次向导反复出现

- 在向导最后一步完成保存，等待进入设备连接页后再退出。
- 如果保存目录或开机启动设置失败，向导不会把失败当作完成；根据界面错误修复权限后重试。
- 不要手动编辑 `config.json` 的版本或向导字段，避免破坏迁移语义。

### 主题透明、阴影或媒体预览异常

- 更新系统显卡驱动和 WebView 运行环境。
- 切换到另一套主题确认是否仅为特定系统效果问题。
- 视频预览依赖系统解码能力；文件记录正常但预览失败时，使用“打开文件位置”交给外部播放器。

## 3. 搜不到设备

### 网络检查

- 两端必须处于可以互相访问的局域网；访客 Wi-Fi、AP/客户端隔离会阻止发现。
- 暂时停用或调整 VPN、代理网卡、虚拟机网卡和容器网络，再重新扫描。
- Windows 网络应优先设为“专用网络”；CopyShare 不会自动把公共网络改为专用网络。
- 默认 UDP 发现端口为 `8764`，默认 TCP/WebSocket 同步端口为 `8765`。

### 防火墙检查

1. 打开「设置 → 网络诊断」。
2. 查看同步、自动发现和手机连接的规则状态。
3. Windows 可使用界面提供的修复操作，为当前 CopyShare 程序创建专用网络入站规则。
4. 第三方安全软件仍可能独立拦截，需要在其规则中允许当前程序和专用网络。

### 改用手动连接

在「设备连接」输入对方 IPv4 地址和监听端口。不要填写公网 IP、回环地址或仅对方本机可见的虚拟网卡地址。

## 4. 能看到设备但无法连接或信任

- 确认连接的设备名称和 ID 与预期一致，不要盲目信任同一 IP 上的新设备。
- 双方都需要完成确认；单向信任不足以交换剪贴板和文件控制消息。
- 修改端口后，确认端口保存成功且同步运行时已经重新监听。
- 手动拒绝后重新发起连接；不要依赖旧的待确认弹窗。
- 如果 IP 被 DHCP 重新分配，优先从自动发现列表重新连接，而不是复用旧地址。

## 5. 已连接但剪贴板不同步

检查以下项目：

- 同步运行时是否正在运行。
- 对应的文本、图片或文件同步开关是否开启。
- 两端是否已完成双向信任。
- 复制内容是否与刚同步过的内容完全相同；重复内容过滤可能跳过它。
- 内容类型是否受系统剪贴板格式限制，例如应用只提供了私有剪贴板格式。
- 日志是否出现写入系统剪贴板失败、队列繁忙或连接心跳超时。

可以用一段新的纯文本做最小复现，再分别测试图片和文件，以判断问题属于连接层还是特定内容类型。

## 6. 文件下载失败、暂停或无法继续

| 现象 | 优先检查 |
| --- | --- |
| 点击后立即失败 | 发送端文件是否仍存在、接收端目录权限、任务是否过期 |
| 下载到一半暂停 | 网络中断、发送端退出、自动重试次数、磁盘剩余空间 |
| 继续下载仍失败 | 发送端源文件是否被修改、`.part` 长度是否异常、设备是否仍受信任 |
| 校验失败 | 源文件变化、网络/磁盘错误；不要手工改名 `.part` 伪装成完成文件 |
| 同批文件被一起显示 | 底层属于同一批次；每个文件仍需独立点击和独立完成 |

处理建议：

1. 保持发送端原文件路径、大小和修改时间不变。
2. 确认接收目录可写且空间足够。
3. 恢复两端连接和信任后，在目标文件记录上继续下载。
4. 如果提示源文件已变化，由发送端重新复制该文件创建新任务。
5. 只有确认不再续传时，才通过应用提供的清理入口删除任务或缓存。

## 7. 历史、收藏夹或缓存问题

- 清理历史不会删除收藏夹，这是设计行为。
- 清理缓存会删除可再生成的历史图片和缩略图，但不会删除 `history.json` 本身。
- 收藏资源按内容哈希管理；删除最后一个引用后才会回收文件。
- 配置、设备和历史使用临时文件、备份与损坏隔离恢复。启动时出现恢复提示时，先保留 `.bak`、`.tmp`、`.corrupt` 文件用于诊断。
- 不要在应用运行时手工同时编辑 JSON 文件，避免与串行保存发生竞争。

## 8. OCR、翻译、通知和快捷键

### OCR 无结果

- 确认图片清晰、方向正确且包含系统 OCR 支持的语言。
- Windows/macOS 使用系统能力；Linux 需要正式安装包提供的 Tesseract 运行环境。
- 先用简单的黑字白底截图验证，再排查复杂背景或特殊字体。

### 翻译失败

- Google 翻译需要可访问对应服务的网络环境。
- AI 翻译检查 API 地址、Key、模型名称和代理；不要在截图或日志中公开完整 Key。
- 使用最短文本测试，区分配置错误、服务限流和内容问题。

### 没有桌面通知

- 在 CopyShare 设置中确认对应通知类型已启用。
- 使用“测试通知”验证系统授权。
- 检查系统勿扰模式和 CopyShare 的通知权限。

### 全局快捷键无效

- 确认该动作已启用，并检查是否与其他软件冲突。
- 录制快捷键时必须包含修饰键。
- 注册失败时原快捷键会被恢复；关闭冲突软件后重新保存。

## 9. 提交问题时应提供的信息

- CopyShare 版本、操作系统和 CPU 架构。
- 问题发生在发送端、接收端还是双方。
- 两端是否同一网段、是否使用 VPN/访客 Wi-Fi/虚拟网卡。
- 相关端口、网络诊断结果和防火墙状态。
- 可复现步骤、期望行为、实际行为和发生时间。
- 同步日志中的脱敏状态与错误；不要提供剪贴板正文、私人文件、API Key 或永久凭据。
